# 音符盒粒子跳动 · 生成器对接文档

本文档定义 **NoteBlockWeb（生成器）** 与 **MiauParticleEffects（模组）** 之间的接口契约。
生成器在生成链式红石结构的同时，额外产出一份「音符盒位置 + 延迟」数据，
通过**命令方块**在结构启动的同一瞬间把数据交给模组，模组按数据驱动弹力球跳动。

> 与旧方案的区别：不再需要 `/mpe noteblock select` 手动框选轨道，也不再需要模组去
> 检测音符盒发声或反推红石走线。时序数据由生成器直接给出，**第一遍播放就完全准确**。

---

## 1. 核心思路

```
       ┌──────────────┐
按钮 ──┤ 红石链输入    │  ← 音符盒依次发声（结构本身，音效由 MC 播放）
   │   └──────────────┘
   │
   └──► ┌──────────────┐
        │ 脉冲命令方块  │  ← 执行 /mpe noteblock chain ~~~ <音符数据>
        └──────────────┘
                  │
                  ▼
        模组按数据播放弹力球动画（纯时间轴，与红石完全解耦）
```

- **一条链 = 一个命令方块 = 一颗弹力球**，多条链之间互不干扰（天然不串轨）。
- 模组不关心红石，只按给定时刻表把球送到指定位置。
- 数据是「相对命令方块的偏移」，因此整条结构可以随意复制、平移。

---

## 2. 命令契约

```
/mpe noteblock chain <anchor> <notes> [选项]
```

### 2.1 `<anchor>` — 锚点

| 写法 | 含义 |
|---|---|
| `~~~` | 以**命令方块自身所在方块坐标**为锚点。生成器一律用这个。 |
| `x,y,z` | 绝对方块坐标锚点（手写调试用）。 |

### 2.2 `<notes>` — 音符数据

格式（用 `\|` 分隔每个音符，一个音符四段）：

```
x,y,z,delay|x,y,z,delay|x,y,z,delay|...
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `x`,`y`,`z` | 整数 | 相对 `<anchor>` 的**方块偏移**。该音符盒的实际坐标 = 锚点 + 偏移。 |
| `delay` | 整数 | **游戏 tick**（20 tick = 1 秒）。见下方语义说明。 |

末尾多余的 `|` 可省略；空段会被忽略。

### 2.3 选项（键=值，可选，放在最后）

| 选项 | 默认 | 说明 |
|---|---|---|
| `trail=` | `24` | 拖尾长度（粒子数），2~256 |
| `curve=` | `arc` | 竖直起伏：`arc` 抛物线 / `sine` 正弦 / `line` 不弹跳 |
| `height=` | `3` | 跳动最大高度（方块），0.5~64 |
| `color=` | 按链自动取色 | 纯色 `#RRGGBB`，或 `rainbow` |
| `gradient=` | — | 渐变 `#RRGGBB,#RRGGBB`，或 `rainbow` |
| `force=` | `false` | 强制显示，不受距离裁剪 |
| `linger=` | `40` | 最后一个音符触发后，小球继续停留多少 tick 再消失；`-1` = 常驻 |

> 多链并存时如果都不指定 `color=`，模组会按命令方块锚点自动分配可区分颜色。

## 3. 坐标与延迟语义（务必对齐）

### 3.1 坐标

- 锚点 = 命令方块的**方块坐标**（整数，例如 `(100, 64, 100)`）。
- 音符盒坐标 = 锚点 + 偏移。
- 小球落点是音符盒的**上表面中心** = 音符盒坐标 + `(0.5, 1.0, 0.5)`。生成器不需要算这个，模组自己处理。

**示例**：命令方块在 `(100,64,100)`，偏移写 `2,0,1` → 音符盒在 `(102,64,101)`。

### 3.2 延迟

`delay` 是**相邻两次发声之间的间隔**，不是绝对时间：

| 位置 | `delay` 含义 |
|---|---|
| 第 0 个音符 | 从**命令方块执行那一刻**到第 0 个音符发声的间隔 |
| 第 i 个音符（i≥1） | 从**第 i-1 个音符发声那一刻**到第 i 个音符发声那一刻的间隔 |

于是每个音符的绝对触发时刻：

```
T(0) = 命令方块执行时刻 + delay[0]
T(i) = T(i-1) + delay[i]
```

小球在第 i 个音符**发声的同一 tick 恰好落到它上表面中心**。

### 3.3 单位换算表（生成器用来算 delay）

| 红石元件 | 延迟（游戏 tick） |
|---|---|
| 中继器 1 档 | 2 |
| 中继器 2 档 | 4 |
| 中继器 3 档 | 6 |
| 中继器 4 档 | 8 |
| 比较器 | 2 |
| 红石火把 | 2 |
| 红石线 | 0（同一 tick 内传播，不计） |
| 音符盒被上一级中继器充能 → 发声 | 0（收到信号即发声） |

`delay[i]` = 从第 i-1 个音符到第 i 个音符之间，链路上所有中继器/比较器/火把延迟的**总和**。

## 4. 生成器需要做的事

1. **放置命令方块**：在每条链式结构的**起点**放一个 **脉冲型（Impulse）** 命令方块。
   - 严禁用循环型（Repeat）——它每 tick 都会执行一次，会不停重置动画。
   - 命令方块的朝向随意；`~~~` 取的是它自身的方块坐标，与朝向无关。

2. **写入指令**：把本文第 2 节的命令填进命令方块，注意：
   - 命令方块执行时会**自动带上权限等级**，无需额外处理。
   - 命令长度上限 **32500 字符**。一条音符约占 `10~14` 字符（如 `2,0,1,8|`），
     因此单个命令方块约可容纳 **2000+ 个音符**；超长请拆成多条链（多个命令方块）。

3. **接线**：把「结构开始」的红石信号**同时**接到：
   - 链式结构自身的红石输入（让音符盒发声）
   - 命令方块的输入（让模组开始动画）

4. **补偿命令方块自身延迟**：
   - 脉冲命令方块被红石激活后，会在**下一个 tick** 执行。
   - 因此 `delay[0]` 应等于「从命令方块执行时刻到第 0 个音符发声」的 tick 数，
     通常 = 「链首红石延迟 − 1」。
   - 若生成器直接以「按钮按下」为 0 点算出链首延迟 `D0`，则应取 `delay[0] = D0 - 1`。
     建议生成器把这一 tick 显式算进去，模组不会做任何猜测。

## 5. 完整示例

假设：命令方块在 `(100, 64, 100)`；4 个音符盒相对锚点分别是
`(3,0,0) (6,0,0) (9,0,0) (12,0,0)`；相邻间隔依次为 10、8、8、16 tick，
其中第一个 10 tick 已经包含了命令方块自身的 1 tick 延迟。

命令方块内写入：

```
/mpe noteblock chain ~~~ 3,0,0,10|6,0,0,8|9,0,0,8|12,0,0,16| curve=arc height=3 trail=24 color=rainbow
```

行为：

| tick | 事件 |
|---|---|
| 0 | 命令方块执行，小球出现在锚点 `(100,64,100)` 上方 |
| 10 | 第 1 个音符盒在 `(103,64,100)` 发声，小球恰好落在它上表面中心 |
| 18 | 第 2 个音符盒在 `(106,64,100)` 发声，小球恰好落上 |
| 26 | 第 3 个音符盒发声，小球落上 |
| 42 | 第 4 个音符盒发声，小球落上 |
| 82 | `linger=40` 到期，小球消失 |

---

## 6. 重复触发与清理

- **同一锚点再次触发** = 重置该链：小球立刻回到锚点，从第 0 个音符重新开始。
  因此单次播放、单曲循环都可以直接复用同一个命令方块。
- **手动清理**：
  - `/mpe noteblock clear` — 移除全部链的小球
  - `/mpe noteblock clear id=<id>` — 移除指定链

---

## 7. 校验清单

生成器产出后请逐条确认：

- [ ] 命令方块是**脉冲型**，不是循环型
- [ ] 锚点写的是 `~~~`
- [ ] 音符数量 ≥ 1，且每个音符都是完整的 `x,y,z,delay` 四段
- [ ] 所有 `delay` 是**非负整数**，单位是**游戏 tick**
- [ ] `delay[0]` 已包含命令方块自身那 1 tick 的执行延迟
- [ ] 偏移量是**相对命令方块**的整数，不是世界绝对坐标
- [ ] 命令总长度 < 32500 字符（超长已拆分）
- [ ] 「开始」信号同时接入了链式结构和命令方块

## 8. 待实现 / 扩展（暂不在本文档契约内）

以下为后续可选项，生成器暂不需要产出：

- 每个音符单独的颜色或音高 → 会让数据段从 4 段变 5~6 段
- 分段多命令方块续播（超长歌曲）
- 与真实音符盒发声对齐的校准（当前为**纯时间轴**，一旦红石被改动会失步，
  需要重新生成数据）
