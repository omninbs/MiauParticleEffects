# 歌词逐字显示 · 生成器对接文档

给 **NoteBlockWeb（红石音乐生成器）** 用的接口契约：把导入的**歌词 JSON** 按「长音断句」
切成一句句歌词，再把每一句连同**每个字的出现时刻**一次下发给 **MiauParticleEffects（模组）**，
由模组按 tick 精确逐字显示。

> 本文只描述**逐字歌词**这条链路。字幕的通用写法（段格式、颜色、动画、时间对齐）见
> [`GENERATOR_TEXT_CN.md`](GENERATOR_TEXT_CN.md)；音符盒弹力球见 [`GENERATOR_CN.md`](GENERATOR_CN.md)。
>
> **分工**：断句算法、时间表生成、命令拼装都在**生成器侧**完成；模组只负责
> 「按给定的 `chars=` 时间表把字一个个显示出来」。模组侧本功能已实现（见第 9 节）。

## 1. 整体链路

```
歌词 JSON（每个字自带 start / duration，单位 tick）
        │  ① 断句（按 duration 阈值）
        ▼
句子列表：每句 = 一串字 + 句首 tick
        │  ② 生成段：段 start = 句首 tick − 1，字 start 改成句内相对值
        ▼
/mpe text chain ~~~ <句1>|<句2>|... chars=<字时间表> [选项]
        │  ③ 写进脉冲命令方块，与红石结构同时激活
        ▼
MiauParticleEffects：整句一次栅格化，按每个字的 start/duration 逐字出现、逐字退场
```

- **一条命令 = 一整首歌的歌词**（一个命令方块、一个脉冲）。
- 生成器不需要知道字宽、行宽：模组会按整句内容自己排布版式，生成器只给**句子中心坐标**。
- 一句歌词 = 一个独立显示实例：**上一句不会因为下一句出现而被清掉**，它会在自己最后一个字
  退场后自然消失（第 9 节）。所以生成器不需要发 `/mpe clear`。

## 2. 输入数据：歌词 JSON

生成器导入的歌词数据必须能还原出「每个字什么时候开始唱、唱多久」。最小字段如下
（字段名可自定，语义必须一致）：

| 字段 | 类型 | 单位 | 含义 |
|---|---|---|---|
| `text` | string | — | 一个**字**（也可以是标点或一个空格 `" "`）。一行一个元素，不要带颜色码。 |
| `start` | int | tick | 这个字**开始出现/开始唱**的时刻，相对歌曲起点（0 = 歌曲第一 tick）。 |
| `duration` | int | tick | 这个字**持续**多少 tick（长音就是大值）。`duration ≥ 1`。 |
| `line`（可选） | int/string | — | 逻辑行号。生成器可用来决定每句的显示位置（第 7 节）。 |

示例：

```json
{
  "title": "失眠",
  "threshold": 4,
  "words": [
    { "text": "今", "start": 100, "duration": 3, "line": 0 },
    { "text": "天", "start": 103, "duration": 3, "line": 0 },
    { "text": " ", "start": 106, "duration": 2, "line": 0 },
    { "text": "真", "start": 108, "duration": 3, "line": 0 },
    { "text": "好", "start": 111, "duration": 12, "line": 0 },
    { "text": "我", "start": 123, "duration": 3, "line": 1 },
    { "text": "还", "start": 126, "duration": 3, "line": 1 },
    { "text": "没", "start": 129, "duration": 3, "line": 1 },
    { "text": "睡", "start": 132, "duration": 20, "line": 1 }
  ]
}
```

要求 / 约束：

- `start` 必须**非递减**（允许相等：同一 tick 出现多个字）。
- `duration ≥ 1`；允许相邻字的区间重叠（连音、和声都无害）。
- **空格也要保留成一个元素**（`" "`）：模组的 `chars=` 时间表按「可见字符」对齐，
  空格算一个字符，删掉空格会造成字数不匹配（第 14 节报错 3）。
- 颜色码（`§4` / `&4`）不占 `chars=` 条目；如果生成器要上色，直接写进句子文字里即可。
  逐字模式下请**每个字单独上色**（`§6今§e天`），这样颜色随字出现。

## 3. 断句规则（核心）

> 大部分歌词是「一 tick 一个字」，整块显示会糊成一大片。所以要按**长音**把歌词切成句子，
> 一句一句显示，上一句显完自然消失，效果才像字幕。

**用户参数**：`threshold`（断句阈值），单位 **tick**，**默认 4**。

**规则**（唯一规则，逐字扫描）：

> 若字 `i` 的 `duration` **严格大于** `threshold`（`duration > threshold`），
> 则字 `i` 是**本句的最后一个字**，字 `i+1` 开始**新的一句**（累计清零、重新累计）。

等价的伪代码：

```text
sentence = []
for word in words:                    # words 已按 start 排序
    sentence.append(word)
    if word.duration > threshold:      # 长音 → 断句
        emit(sentence); sentence = []
if sentence not empty: emit(sentence)  # 收尾
```

几个必须注意的细节：

1. **断句发生在长音字的后面**，不是前面。长音字本身属于当前句，它要「唱完」整句才结束。
2. **长音字的 duration 不会被截断**：句子的显示时长由「最后一个字的 start + duration」决定，
   所以长音字会完整显示 12 / 20 tick 之后整句才一起退场——这正是用户说的
   「等待这个长 duration 的字显示完成后清空累计」。
3. 阈值调大 → 句子更长（一次显示更多字）；阈值调到很大（例如 72000）→ 整首歌词只切成一句。
4. 阈值是**严格大于**判定：`duration == threshold` 不断句，`duration == threshold + 1` 断句。
5. 若用户希望「标点也断句」，可以在生成器侧额外加一条可选的辅助规则
   （例如文字是 `，。！？` 时也断）。**默认不加**，只按 duration。
6. 只有 1 个字的句子是合法的（一个字的长音就够了）。

## 4. 用户可配置项

生成器需要暴露给用户的参数（括号内为模组默认值，生成器可原样透传）：

| 参数 | 单位 | 默认 | 作用 |
|---|---|---|---|
| `threshold` | tick | `4` | 断句阈值，见第 3 节 |
| 句子位置 `x,y,z` | 方块（相对锚点，可为小数/负数） | 由生成器决定 | 每句的**文字中心**（第 7 节） |
| `scale=` | 方块 | `1.0` | 字高 |
| `color=` / `gradient=` | — | `#FFFFFF` | 纯色 / 渐变 / `rainbow` |
| `density=` | 0.01~1 | 配置值(0.1) | 粒子密度（越小越清晰、粒子越多） |
| `enter=` | tick | `10` | 每个字的入场动画时长（逐字模式下建议 `0~2`） |
| `exit=` | tick | `10` | 每个字的退场动画时长（建议 `2~4`） |
| `in=` / `out=` | — | 无 | 每个字的入场 / 退场动画（第 8 节白名单） |
| `fade=` | — | `none` | `in` / `out` / `both`，逐字淡入淡出 |
| `towards=` | 角度 | `0` | 文字朝向 |
| `id=` | 字符串 | 锚点坐标 | 链 ID（同一 ID 再次执行 = 重置重播） |
| `linger=` | tick | `0` | 整条链播完后再保留多久；逐字模式一般不用 |

## 5. 命令语法

```
/mpe text chain ~~~ <段1>|<段2>|...|<段N> [全局选项]
```

- `~~~`：以命令方块自身的方块坐标为锚点。**生成器一律用它**，结构整体平移/复制无需改数据。
- 每段对应**一句歌词**：

```
x,y,z,start,duration,文字[;段内选项]
```

| 段字段 | 含义 |
|---|---|
| `x`,`y`,`z` | 相对锚点的方块偏移（小数/负数可以）。**= 整句文字中心**。 |
| `start` | 这一句从**命令方块执行那一刻**算起的 tick（绝对时刻）。见第 6 节。 |
| `duration` | 逐字模式写 **`0`**（或省略该字段），模组自动取「最后一字的 `start + duration`」。 |
| `文字` | 句子正文。空格写 `_`；支持 `§` / `&` 颜色码；**不能含 `\|` `;` `,`**。 |
| `段内选项` | 用 `;` 连接，覆盖全局选项，例如 `;chars=...` |

- 逐字时间表（新增，模组已实现）：

```
chars=<字start>:<字duration>,<字start>:<字duration>,...
```

| 项 | 含义 |
|---|---|
| 条目数 | **必须等于句子的可见字符数**：`§x` / `&x` 颜色码不算，**空格算一个**。 |
| `字start` | 这个字相对**本段 `start`** 的 tick 偏移（`≥ 0`） |
| `字duration` | 这个字从出现到**开始退场**的时长（`≥ 1`） |

- 多个字可以写相同的 `字start`（同一 tick 一起出现）。
- `chars=` 写在段内（`;chars=...`）或全局（空格分隔）都行。
- 逐字模式下**段字段 `duration` 只用来校验**：写 `0` / 省略 = 自动推导；
  写了比时间表更小的值 → 模组报错（避免静默截掉最后几个字）。

## 6. 时间基准与命令方块延迟

- 模组的段 `start` 从**命令方块执行那一刻**计时（tick 0 = 执行瞬间）。
- 脉冲命令方块被红石激活后，会在**下一个 tick** 才执行。
- 因此：若生成器以「按钮按下的那一刻」为 0 点、算出的句子首字时刻是 `T`，
  则应写 **`start = T − 1`**。
- `字start` 相对段 `start`，所以 `字start = word.start − T`（句内相对值，首字通常是 0）。

数值示例：句首时刻 `T = 100`（相对按下），则段 `start = 99`；首字 `字start = 0`，
第二字 `start=103` → `字start = 3`。

> 这个 `−1` 与 `/mpe noteblock chain` 的 `delay[0] = D0 − 1` 完全一致：
> 把两条命令放进同一个（或同时激活的两个）脉冲命令方块，歌词与弹力球就能对齐。

## 7. 位置与版式

- 段的 `x,y,z` 是**整句文字的中心**。模组会先按整句内容把版式算好（字与字的位置固定），
  再按时间让每个字出现——**未到时刻的字占位但不画**，所以句子不会一边显示一边跳动。
- 生成器只需要给「这一句显示在哪」：例如屏幕中央上方一行、居中对齐。
- 多行歌词：给不同行不同的 `y`（或不同 `z`）即可，模组不做自动换行。
- 句与句默认可以**时间重叠**（上一句还没退场，下一句已经开始），这在副歌长音时很正常；
  如果不想重叠，生成器可以自行把下一句的 `start` 推迟到上一句结束之后，或把两行放到不同 `y`。

## 8. 动画与逐字模式的限制

逐字模式下「什么时候出现」由时间表决定，所以以下动画**与时间表语义冲突，模组会直接报错**：

| 禁用 | 原因 |
|---|---|
| `in=` / `out=` 里的 `typewriter` | 它自己就是「逐字出现」的另一种实现 |
| `in=` / `out=` 里的 `wipe` | 按连续边线擦除，与按字显现冲突 |
| `in=` / `out=` 里的 `spacing` | 字间距动画会破坏逐字版式 |
| `in=` / `out=` 里的 `scatter` | 逐字随机爆散会互相穿插 |

逐字模式**支持**（作用范围是**单个字**，以字中心为基准）：

```
scale:shrink|enlarge     zoom:in|out        flip:horizontal|vertical
rotate:roll|yaw|pitch    slide:up|down|left|right
drop:down|up|left|right  bounce:drop|rise   clarity:clear|blur
fade=in|out|both         move=dx,dy,dz,时长,曲线（整句位移，显示期生效）
```

推荐写法（歌词字幕）：

```
enter=0 exit=3 fade=both in=scale:enlarge
```

含义：字立刻出现（`enter=0`），退场时 3 tick 内缩小淡出。

## 9. 模组侧已实现的行为

生成器可以依赖以下语义（模组已实现，不需要生成器做任何补偿）：

1. **一句一个显示实例**：每段歌词到点创建，最后一批字退场完成后自己删除。
   上一句与下一句互不影响，可以重叠；不需要 `/mpe autoclear`。
2. **逐字出现**：字 `c` 在 `段start + 字start` 时刻开始出现，`字duration` 后开始退场，
   退场动画长度取段的 `exit=`。
3. **字的入场/退场**：入场动画时长 = `min(enter=, 该字duration)`；退场用 `out=` + `exit=`。
4. **整句生命周期** = `delay + max(字start + 字duration) + exit`（tick）。
5. **帧驱动渲染**：字边界的动画按渲染帧（~60FPS）插值，不会一格一格跳。
6. **同一 tick 多字 / 多句同时显示**都支持，互不干扰。
7. 段的 `start` 到点后，如果整句已经过期（例如 replay 跳进度），模组会跳过它，不会补播。
8. 协议层新增了「逐字时间表」字段，**客户端与服务端都要装同一版本模组**。
9. `/mpe text chain clear [id=...]`、`/mpe text chain status` 行为不变；
   逐字实例被强制清理时立即消失（不会重播已经出现过的字）。

模组实现位置（维护者参考）：

| 文件 | 作用 |
|---|---|
| `model/CharTiming.java` | 单个字的时间表条目（`start`, `duration`） |
| `model/TextDisplayParams.java` | 新增 `charTimings` 字段、`perChar()`、`charSpanTicks()` |
| `command/MiauParticleEffectsCommand.java` | 解析 `chars=`、可见字符数校验、动画白名单校验 |
| `protocol/PayloadCodecs.java` | `chars=` 的编解码 |
| `client/raster/FontRasterizer.java` | 提供每个字的水平中心（字级缩放/旋转基准） |
| `client/display/TextInstance.java` | 逐字时间轴渲染（`spawnPerChar`） |

## 10. 完整示例

数据：第 2 节的 JSON，`threshold = 4`，题目位置在命令方块上方 2 格（`0,2,0`），
假设两行歌词都显示在同一位置（真实场景请换行，见第 7 节）。

**① 断句**

| 句 | 字 | 句首 `T` | 字相对 start | duration | 句末时刻 |
|---|---|---|---|---|---|
| 1 | 今 天 ␣ 真 好 | 100 | 0, 3, 6, 8, 11 | 3, 3, 2, 3, **12** | 11 + 12 = 23 |
| 2 | 我 还 没 睡 | 123 | 0, 3, 6, 9 | 3, 3, 3, **20** | 9 + 20 = 29 |

`好`（12 > 4）与 `睡`（20 > 4）是长音 → 各自是句末，所以只切成 2 句。

**② 生成命令**

```
/mpe text chain ~~~ 0,2,0,99,0,今天_真好;chars=0:3,3:3,6:2,8:3,11:12|0,2,0,122,0,我还没睡;chars=0:3,3:3,6:3,9:20 enter=0 exit=3 fade=both in=scale:enlarge
```

拆开看：

- 第 1 段：`0,2,0,99,0,今天_真好;chars=0:3,3:3,6:2,8:3,11:12`
  - `start = 100 − 1 = 99`
  - 文字 `今天_真好`（`_` → 空格，5 个可见字符），`chars` 也是 5 项 ✔
  - `duration` 写 0：模组自动算成 23
- 第 2 段：`0,2,0,122,0,我还没睡;chars=0:3,3:3,6:3,9:20`
  - `start = 123 − 1 = 122`
  - 4 个字 / 4 项时间表 ✔

**③ 时间线（相对命令方块执行）**

| tick | 事件 |
|---|---|
| 0 | 命令方块执行，客户端拿到整首歌的歌词时间轴 |
| 99 | 第 1 句在 `(0,2,0)` 开始，字「今」出现 |
| 102 / 105 / 107 | 「天」「␣」「真」依次出现 |
| 110 | 「好」出现，并停留 12 tick |
| 122 | 第 2 句开始，「我」出现（此时第 1 句的「好」还在显示 → 允许重叠） |
| 132 | 第 1 句「好」开始退场，3 tick 内消失 |
| 141 | 第 2 句「睡」开始退场 |
| 144 | 第 2 句整句删除 |

## 11. 生成算法伪代码

```text
# ---------- ① 读歌词 ----------
words = json.words                                 # 必须已按 start 升序，start >= 0
threshold = user.threshold (默认 4)                 # 单位 tick

# ---------- ② 断句 ----------
sentences = []
current  = []
for w in words:
    current.append(w)
    if w.duration > threshold:                     # 严格大于 → 本句结束
        sentences.append(current)
        current = []
if not current.isEmpty():
    sentences.append(current)

# ---------- ③ 每句 → 一个段 ----------
segments = []
for s in sentences:
    T = s[0].start                                 # 句首时刻（相对歌曲起点，即按钮按下）
    segStart = max(0, T - 1)                       # 命令方块自身 1 tick 延迟补偿
    text = ""
    chars = []
    for w in s:
        rel = w.start - T                          # 句内相对偏移
        chars.append(rel + ":" + max(1, w.duration))
        text += sanitize(w.text)                   # 见下
    pos = positionFor(s)                           # 你决定：x,y,z（句子中心）
    segments.append(
        pos.x + "," + pos.y + "," + pos.z + "," + segStart + ",0,"
        + text + ";chars=" + join(chars, ",")
    )

# ---------- ④ 拼命令 ----------
command = "/mpe text chain ~~~ " + join(segments, "|")
          + " enter=0 exit=3 fade=both in=scale:enlarge"   # 全局默认选项
writeIntoImpulseCommandBlock(command)

# sanitize:
#   空格            → "_"
#   句子内不能出现  "|" ";" ","      （这三个是段分隔符）
#   颜色码用 § 或 &   （每个字单独上色，例如 §6今§e天）
#   '&' 只在紧跟颜色码字符时才是颜色码，普通 '&' 会被原样显示
```

## 12. 命令长度与拆分

- 命令方块命令上限 **32500 字符**。
- 估算：每个字约占 `(chars 项 ~6 字符) + (正文 1~2 字符)` ≈ 8~10 字符；一句 10 字 ≈ 100 字符。
  一首歌 60 句 ≈ 6000 字符，**通常一条命令足够**。
- 超过上限时按句子拆分，拆成多个命令方块，用 `id=` 区分，并让它们**同时**被激活
  （各自的消息独立，事件之间不需要交互）：

```
/mpe text chain ~~~ <前半段...> id=lyric-a
/mpe text chain ~~~ <后半段...> id=lyric-b
```

- 注意：不同命令方块里的段 `start` 都相对**自己的执行时刻**，所以同时激活即可对齐。

## 13. 校验清单

生成器产出后逐条确认：

- [ ] 每个字都有 `start`（≥0）与 `duration`（≥1）
- [ ] `words` 按 `start` 非递减排序
- [ ] 断句用的是 `duration > threshold`（严格大于），长音字**属于当前句**
- [ ] 每句的段 `start` = 句首 tick − 1（补命令方块 1 tick 延迟）
- [ ] `chars=` 项数 **= 句子可见字符数**（空格算 1，`§x`/`&x` 颜色码不算）
- [ ] 每项的 `字start` = `word.start − 句首tick`，`字duration` = `word.duration`
- [ ] 段 `duration` 写 `0`（或省略），让模组按时间表推导
- [ ] 句子文字里没有 `|` `;` `,`，空格已写成 `_`
- [ ] 逐字模式没有用 `typewriter` / `wipe` / `spacing` / `scatter`
- [ ] 命令是**脉冲型**命令方块，锚点写 `~~~`
- [ ] 命令总长 < 32500 字符（超长已按句拆分并同时激活）
- [ ] 「开始」信号同时接入红石结构与命令方块

## 14. 报错对照表

模组解析失败时会把错误信息返回给命令方块执行者（单人存档里会直接在聊天栏看到）：

| 报错 | 原因 | 修法 |
|---|---|---|
| `chars= 有 N 项，但文字 '...' 有 M 个可见字符` | 时间表与字数不一致（最常见） | 空格也算一个字符；确认没有漏掉 `_` 或多余条目 |
| `chars= 第 k 项 '...' 格式错误，应为 start:duration` | 少了冒号 | 每项都写 `<start>:<duration>` |
| `chars= 第 k 项 start 取值应在 0 ~ 72000` | 负数或超范围 | 用句内相对值（首字 0） |
| `duration=... 小于逐字时间表最后一字的结束时刻 ...` | 段里写了过小的 `duration` | 段 `duration` 写 `0` 或省略 |
| `逐字模式（chars=）不支持 in=typewriter` | 用了冲突动画 | 换 `scale` / `fade` 等（第 8 节） |
| `第 k 段的 duration 至少为 1 tick（逐字模式可用 chars= 让模组推导）` | 段写了 `0` 但没有 `chars=` | 补 `chars=`，或写 ≥1 的 duration |
| `至少需要 1 段歌词` | 段数据为空 | 检查拼装时是否写了 `\|` 分隔 |

## 15. 调试

```
/mpe text chain status              查看存活的歌词链（id / 段数 / linger）
/mpe text chain clear               清除全部歌词链
/mpe text chain clear id=<ID>       清除指定链
/mpe help textchain                 查看完整参数帮助（含 chars= 说明）
```

模组收到链后会回一条反馈，包含 `id`、锚点、段数与总时长（tick / 秒），可以用来快速核对
「我算的句子数量、总时长是否正确」。
